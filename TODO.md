## 1 · Security & Access Control

### Critical

- [V] **SEC-C1 · Unauthenticated registration grants the first caller MASTER** — [users.py:14-20](backend/routers/users.py#L14-L20) · `[REDESIGN]`
  **Evidence:** The route decorator carries no authentication dependency, and the role is assigned as "master" when the user count is zero.
  **Why it matters:** On any fresh or wiped deployment, the first anonymous caller on the network becomes the system administrator with full-fleet visibility and role-assignment rights. This is unauthenticated total takeover, not privilege escalation.
  **Fix:** Require authentication and the role-assignment permission on this route. Remove the count-based role branch entirely and bootstrap the initial administrator out-of-band through an environment-gated command that is not reachable over HTTP.

- [V] **SEC-C2 · System initialization endpoint is unauthenticated** — [setup.py:13-14](backend/routers/setup.py#L13-L14) · `[REDESIGN]`
  **Evidence:** Besides login and the root endpoint, this is the only route with no current-user dependency. It seeds the Master profile that carries role-assignment and view-all rights.
  **Why it matters:** It completes the SEC-C1 takeover chain — an anonymous caller can create the privileged profile and then claim it.
  **Fix:** Gate behind the same out-of-band bootstrap path as SEC-C1, or remove the endpoint and fold initialization into the seed/migration flow.

- [V] **SEC-C3 · Any authenticated user can set any equipment to any status** — [verifications.py:23-55](backend/routers/verifications.py#L23-L55) · `[REDESIGN]`
  **Evidence:** Equipment is resolved by ID with an existence check only — no ownership, holder, or unit check — and the reported status is a free-form string written straight onto the record.
  **Why it matters:** Textbook IDOR on the most sensitive write in the system. Any soldier can iterate IDs and rewrite the status of every asset in the force, corrupting the readiness metric that command reporting depends on. Arbitrary strings also poison the analytics counter, which matches on one exact value.
  **Fix:** Apply the same scoping the equipment router uses, constrain the status to a shared enumerated type, and require that the caller holds or administers the item.

- [V] **SEC-C4 · Every seeded account, including MASTER, shares one password** — [seed_data.py:135](backend/seed_data.py#L135) · `[ABANDON]`
  **Evidence:** A single hashed literal is reused for all seven demo users across every privilege level.
  **Why it matters:** Wherever the seed has ever run, a known-credential administrator backdoor exists.
  **Fix:** Generate per-account random passwords at seed time and print them once; refuse to seed outside an explicitly flagged local environment. Do not carry this pattern into the rewrite.

- [V] **SEC-H1 · The hierarchy model is inert for all real data** — [equipment.py:31](backend/routers/equipment.py#L31), [users.py:26-35](backend/routers/users.py#L26-L35), [equipment.py:99](backend/routers/equipment.py#L99) · `[REDESIGN]`
  **Evidence:** The hierarchy field every scoping query reads is populated only by the seed script. User registration collects battalion and company but never maps them onto a hierarchy path; equipment creation sets no hierarchy at all.
  **Why it matters:** This is the single most consequential defect. For all non-seed data the field is null, prefix matching against null excludes the row, and every non-master user silently falls through to seeing only what they personally hold — while equipment created through the API becomes invisible to everyone but MASTER. The security model demonstrated on seed data does not exist in the running product.
  **Fix:** Decide the rewrite question at the end of this document first. As an interim repair, populate the hierarchy on both user and equipment creation and backfill existing rows.
  **Sub-document:** the rewrite question resolved to *replace*, so this item is being executed as a model replacement across 13 entries — see [TODO-SEC-H1.md](TODO-SEC-H1.md). That work also closes SEC-H2, SEC-H4, DATA-H9, DATA-M15, DATA-M16 and DATA-M17.
  **Closed at H1-13.** All 13 entries in `TODO-SEC-H1.md` are complete. The materialized-path model — `unit_hierarchy`, `unit_path`, `battalion`, `company` as authorization inputs — is gone; every scoping and authority decision now resolves through the group DAG (`Group`/`GroupEdge`/`GroupClosure`), `GroupMembership`, and `Grant`-backed `Capability` checks (`may()`/`require()`/`require_global()`). `SYSTEM_MAP.md` is synced to match throughout, not just in its access-control section.

- [V] **SEC-H2 · Unanchored prefix matching leaks across sibling units** — [equipment.py:41-46](backend/routers/equipment.py#L41-L46), [reports.py:39-44](backend/routers/reports.py#L39-L44) · `[REDESIGN]`

  **Why it matters:** A commander of a single-digit battalion path also matches every multi-digit sibling path sharing that prefix, so they see units they have no authority over. Real cross-unit disclosure, not a theoretical one.
  **Fix:** Anchor the comparison on a path separator, and handle the exact-match case explicitly. Fix once in the shared helper proposed in DATA-H9, not twice.

## 2 · Correctness & Data Integrity

### Critical

- [V] **DATA-C1 · No migration tooling exists** — [main.py:33](backend/main.py#L33) · `[CARRY FORWARD]`
  **Evidence:** The schema is created by the ORM's create-all call at import. There is no migration framework, directory, or dependency anywhere in the repository.
  **Why it matters:** Create-all only creates *missing tables* — it never alters an existing one. Every schema fix in this document is therefore unshippable to an existing database.   **Fix:** Adopt a migration framework, generate an initial migration matching the current models, and route all future schema change through it. This is the first infrastructure decision, ahead of every other item here.

- [V] **DATA-C2 · The seed script destroys the entire schema with no guard** — [seed_data.py:19-22](backend/seed_data.py#L19-L22) · `[CARRY FORWARD]`
  **Evidence:** A raw cascading schema drop and recreate runs at the top of the seed routine, against whichever database the environment points at. No environment check, no confirmation, no dry run.
  **Why it matters:** Total data loss is one documented command away — and the command is documented in the repository's own notes file. Combined with DATA-C1, this is currently the project's *only* migration strategy.
  **Fix:** Require an explicit environment flag, refuse to run against anything not marked local, and separate the destructive reset from ordinary seeding.

## The primary rewrite decision

Every entry tagged `[REDESIGN]` in the Security section traces back to one question this document deliberately does not answer:

**The hierarchy model is the system's core security dimension, and it is inert for all data created through the API.** It is elaborately modelled, seeded, documented, and displayed — and written by no application code path. Six of its permission flags are checked by no router, and a hardcoded name list overrides the ones that are.

Two options:

1. **Repair in place** — populate the hierarchy on user and equipment creation, backfill existing rows, anchor the prefix matching, and enforce the six orphaned permissions. Lower cost; retains a materialized-path design whose prefix semantics already produced a cross-unit leak.
2. **Replace** — model units as real rows with real relationships and derive scoping relationally. Higher cost; eliminates the entire class of defect represented by SEC-H1, SEC-H2, and DATA-M16.

**This decision should be made before any `[REDESIGN]` item is worked**, because it determines whether those items are fixed or discarded.
