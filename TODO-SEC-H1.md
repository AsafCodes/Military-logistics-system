# TODO — `SEC-H1` Access Model Replacement

> **Status:** Phase 1 in progress. H1-1 implemented, not yet verified or committed.
> **Parent:** [TODO.md](TODO.md) · SEC-H1 · *The hierarchy model is inert for all real data*
> **Method:** Three deep audits of the hierarchy surface (data model, read paths, write paths), plus a design pass that reduced the access question to a single relation. Every file:line below was verified against the working tree, not inferred.
> **Scope:** 13 entries in 4 phases. SEC-H1 turned out to be a defect in the *encoding*, not in the missing writes, so this replaces the model rather than patching it.

**Disposition legend**
`[ADD]` — new code; nothing existing changes behaviour, suite stays green.
`[CUTOVER]` — existing behaviour moves onto the new model; legacy code stops being read.
`[DELETE]` — legacy removed once nothing reads it.

**Why this is not a patch.** The original fix — populate `unit_hierarchy` on create — would have made the string API-writable. [dependencies.py:88](backend/dependencies.py#L88) compiles `startswith()` to an **unescaped `LIKE`** on both dialects, so a user created with `unit_hierarchy = "%"` would see every asset in the force, and `"188_53"` would match `188/53` with no malice required. The encoding is wrong, not under-validated.

**Verified starting state**

| Check | Result |
|---|---|
| Representations of "unit" in the model | **Four** — `battalion`/`company`, `unit_path`, `unit_hierarchy`, `Location.unit_path` |
| Written by application code | `battalion`/`company` only — and **no query reads them** |
| `unit_path` writers | **None** outside test fixtures |
| `unit_hierarchy` writers | `seed_data.py` only |
| Scoping implementations | **Two**, already diverged (`dependencies.py:63-88` vs `reports.py:28-54`) |
| Production data at risk | **None** — 1 MASTER user, 0 equipment rows |

**Decisions taken (2026-08-21) — do not relitigate**

1. **Replace, not repair.** [TODO.md:545](TODO.md#L545)'s primary rewrite decision resolved to option 2.
2. **DAG, not tree.** A thing may sit in several groups. Ancestry lives in a closure table.
3. **One unified relation.** Visibility is not a special case — it is `may(P, VIEW, R)`. Extent and authority collapse into the same mechanism.
4. **Clean cutover.** The system is not in production: no dual-writes, no compatibility shims, no legacy path support.
5. **Additive → cutover → drop.** Legacy columns come out in Phase 4, not Phase 1, so no phase boundary lands on a broken tree.

**The model**

```
desc(G)      = { H : G ⊑ H }              down-set of G, G included
extent(P,C)  = ⋃ { desc(g.group) : g ∈ grants(P), g.capability = C }
may(P,C,R)   ⟺ group(R) ∈ extent(P,C)
```

Four primitives: **Group** (a set), **Edge** (direct containment), **Membership** (a user is *in* a group), **Grant** (a user holds a capability *over* a group). Membership and grant are different: a private is a member of Co_A with no grant; a battalion commander holds a grant over Bn53.

`Group` is polymorphic on `kind` (`Unit`, `TaskForce`). The algebra is deliberately **kind-agnostic** — `desc`, `extent` and `may` never branch on kind, so a new group kind requires zero changes to the scoping layer. Any `if kind == ...` in a scoping path is a design error.

- [ ] **H1-2 · Closure engine** — [backend/authz.py](backend/authz.py) · `[ADD]`
  **Scope:** `rebuild_closure(db)` — read all edges, compute the transitive closure, delete every closure row, bulk-insert, emitting a `depth=0` self-row per group so `desc(G)` includes `G`. `detect_cycle(edges)` via topological sort. `add_edge(db, parent, child)` rejecting self-edges and any edge that would close a cycle (module-level `CycleError`), then rebuilding. `remove_edge(db, parent, child)`, then rebuilding.

  **Out of scope, recorded under SEC-H5:** `GET /users` returns the full roster — military ID numbers and every user's permission matrix — with no gate of any kind. **Phase gate:** no router reads a `Profile` boolean or compares a role string. **Met at H1-10.** `is_master` and `verify_admin_access` are deleted; the only remaining mentions anywhere in `backend/` are docstring prose recording what was removed. `models.UserRole` survives as a *data* column — `bootstrap_admin` and `create_user` write it, `promote_user` updates it, the frontend's Admin link reads it — but no backend authorization path consults it.
